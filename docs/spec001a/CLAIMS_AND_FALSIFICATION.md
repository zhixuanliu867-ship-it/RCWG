# RCWG 的研究主张、证据与反证条件

状态：研究假设/实验设计，尚无真实模型主矩阵结果。日期：2026-09-19。

## 1. 建议的中心主张

**工作流生成的实用能力，是在给定数据与资源条件下选择语义可靠、资源可行并能适应条件变化的执行程序；单一条件下的可执行性或平均耗时不足以确定这种能力。**

研究对象保留在自然语言计算工作流。GraphRAG属于其中图文联合任务族。评价算法选择、分解、数据传递、调度与证据义务的联合结果。

## 2. 一个可证明的分析例子

两条独立分支各需时间d、私有工作内存m，完成即释放，输出可忽略。共同基础驻留m0。忽略干扰与调度开销作为明确的分析假设。

串行：T=2d，peak=m0+m。
并行：T=d，peak=m0+2m。

预算m0+m <= B < m0+2m时，串行可行而并行不可行。预算B>=m0+2m且时间上限允许时，两者可行，并行更快。两方案可以共享同一逻辑DAG、节点数、边数和工作量，仅物理调度/并发声明不同。

因此，预算缺省的语义通过分和节点/边计数不能决定所有资源条件下的可行/时延优劣。这个小命题来自条件化可行集合，不主张为新的调度理论。实际机器上d、m和并行干扰需要测量。

同理，复制与引用共享、不同粒度的语义调用会改变数据搬运、驻留与证据覆盖。哪些改变能改善真实模型结果，应由实际实验决定。

## 3. 外部工作核对与差异定位

TPS-Bench（arXiv:2511.01527；本次核查v1正文）：任务完成、工具选择、token、时间、轮数与cost-of-pass；同时已讨论并行/顺序调度。因此“首次评估效率或调度”不能作为本工作的独创性主张。

ComfyBench（arXiv:2409.01392及作者项目页）：用pass/resolve检验工作流可执行和满足任务。

Chat2Workflow（arXiv:2604.19667v1）：包含平台导入、实际执行和结果验收，并评估多轮需求。应准确描述这些已有内容。

GraphFlow（arXiv:2605.22566；本次仅核查摘要）：涉及工作流管理和KV-cache内存优化。说明内存/工作流效率也存在邻近研究；本次未完成该文方法和实现审计。

当前选择的差异化方向：统一可测执行器；同任务跨资源/数据条件的可行性与重规划配对；算法级物理实现选择；多维资源/信息流证据；受控干预检验失败机制。它是基于已核查工作形成的定位判断，尚不是对全部2026年文献的排他性首创证明。

## 4. 三层证据

| 层 | 研究问题 | 需要的证据 | 不足时如何解释 |
|---|---|---|---|
| H1 有条件的能力缺口 | 高语义成功是否伴随预算/近优缺口？模型相对表现是否随条件改变？ | 原主矩阵的联合S/V/效率/覆盖，配对条件交互，跨族效应与区间 | 结论限定在观测条件，报告效应小或不确定 |
| H2 机制定位 | 哪些缺口来自算法、驻留/搬运、调度或证据流？ | E3/E4/E5的语义保持干预和阴性对照；原计划/变体的核验结果与资源差 | 相关性诊断保留，不将计数相关当作因果解释 |
| H3 适配与改进 | 条件信息或协议变化能否实际改善可行性？ | E2 Adaptive/Frozen，P1/P0，资源/数据条件交互和未见组合 | 无提升也如实报告；不能凭模型解释文本证明已学会优化 |

必须区分：工程注入缺陷（检查器能否检测）、真实生成计划缺陷（真实发生率）、修复干预（局部可改善空间）、真实部署（外层延迟/经济成本）。

## 6. 明确的反证条件

若冻结候选本身覆盖差且远离合理实现，则近优差距不能支持生成器能力缺口。若计量干扰/云噪声解释了主要差异，则性能结论不成立。若只靠人为注入坏计划才能获得差异，则不能声称真实生成器存在同样频率的问题。若所有条件下一个固定计划都同样优，则该任务对条件适配无鉴别力，应在开发审核中标记。若E8不复现，就区分构造任务结论和外部有效性。
