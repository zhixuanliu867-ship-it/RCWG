# CLOUD001 versioned engineering profile

The approved change plan is immutable; its private owner receipt is validated
separately. An approval is never an acceptance result. Credentials, input gold,
raw provider bodies and runtime evidence stay outside public Git.

`rcwg_cloud.prompts` assembles and audits the final provider payload, including
the same public syntax, schema, catalog, worklist and development example in P0
and P1 physical stages. The only added P1 user material is its actual logical
response. This is PROTO_PATCH_AUDIT_F01, not a modification of protected v1.1.

`rcwg_cloud.contracts` binds closed phase manifests to the project, service
identity, image/source hashes, owner-controlled GCS object generations, 24-hour
official price evidence and independent C1 review. The old pilot cannot supply
new authorization. Cloud CLI has no simulation or alternate endpoint options.

`rcwg_cloud.admission` uses a fixed ticket-wide phase claim and six fixed slot
objects with GCS conditional creation. Unknown write acknowledgements stop
before dispatch; unknown model outcomes are not retried or refunded. IAM grants
no deletion of claims, reservations or evidence. The budget is client admission,
not a provider billing cap and not proof of provider exactly-once behavior.

`rcwg_cloud.runtime` runs the unchanged Linux F1 supervisor, preserves invalid
plans and FAIL answers, then writes an archive and final marker. No final marker
means incomplete evidence. OOM/kill outcomes require external reconciliation
with the original two-slot denominator. Runtime self-reports cannot independently
prove the actual OCI digest, platform terminal status or GCS persistence.

`rcwg_cloud.review` reopens downloaded hashes, strict provider responses,
physical payload parity, execution seals and independently recomputed answers.
Its artifact pass alone is not CLOUD001_F1_ENGINEERING_ACCEPTED. An owner-side
platform/image/identity/configuration and GCS generation/reservation read joins
that evidence before any C1 or full-ticket acceptance.

`scripts/cloud001_build_context.py` packages clean committed allowlisted source,
never private materials. `scripts/accept_cloud001.py` is a Linux 3.12.14 offline
gate. Existing target tests/Windows tests/CI and actual cloud results remain
separate. The only implemented execution profile remains 5 operators / 8
branches, reference CPU semantics, unverified formal memory isolation.
