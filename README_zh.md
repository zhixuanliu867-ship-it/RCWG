# WELD

**Work, Execution, and Lifecycle Diagnostics：工作量、执行与生命周期诊断。**

[英文论文](weld_release/paper/WELD_ACL_EN.pdf) · [中文论文](weld_release/paper/WELD_ACL_ZH.pdf) · [English](README.md) · [详细复现说明](docs/weld/REPRODUCING.md)

作者：Zhixuan Liu、Qi Yan，Northeastern University。Qi Yan 为通讯作者。当前版本为 2026 年 10 月研究稿。

## 研究问题

模型决定 Agent 做哪些工作、怎样组合结果，以及条件变化后保留或重做哪些部分。WELD 用模型生成的动态工作流、固定的原生工人、任务级验证和版本化记录，测量这些决策的实际效果。

1. **同一任务都做对以后，哪些方案做了更少的工作？** 使用各场景原生工作量向量比较，区分支配、相同和资源权衡。调用次数只是其中一个观测值。
2. **减少的工作兑现了多少时间收益？** 比较工作量节省与时间节省，区分在线端到端时间、扣除本地准入等待的时间，以及固定响应的原生回放。
3. **条件变化后，模型是否做出了正确且代价合理的调整？** 从同一完成状态分别施加相关变化和无关变化，检查修复、保持、复用和新增工作。

正确率按所有尝试计算。工作量和时间的配对比较要求两个方案都通过验证，同时公开有效比较池的大小。各指标分别报告，没有加权总分。

## 最终实验

五个场景为图检索、代码审查与影响分析、关系数据分析、遥测调查、应用状态操作。共 100 个父任务、20 个来源簇，每个场景 5 个简单任务和 15 个中等任务。每个父任务包含初始、相关变化、无关变化三个条件。10 个模型各生成两次，得到 6,000 个逻辑阶段；固定响应的原生回放包含 8,874 次执行。

- 5,006 个正确初始方案对中，2,241 对存在原生工作量支配，372 对存在资源权衡。
- 187 对方案的工具调用数相同，主要原生工作量不同。
- 中等任务中，在线工作量节省与时间节省的等父任务均值差为 31.6 个百分点；扣除本地准入等待后为 14.5 个百分点。原生执行通常能兑现节省，在线交互进一步影响兑现程度。
- 1,479 个正确初始结果中，相关变化后 807 个仍有效，无关变化后 1,468 个仍有效，分别为 54.6% 和 99.3%。

## 阅读与复现

先读论文摘要和引言，再读方法图、指标定义和三组发现。核对数字时查看 `weld_release/data/`。理解实现时查看 `weld_release/benchmark/src/`，其中 `tiered.py`、`dataflow.py`、`runtime.py` 分别对应最终任务接口、动态数据流和运行时记录。

```bash
git clone https://github.com/zhixuanliu867-ship-it/WELD.git
cd WELD
python weld_release/scripts/reproduce_results.py
```

该命令只依赖 Python 标准库，核验公开文件的哈希并重新计算主要结果，不调用付费 API。输出为 `weld_release/reproduced/summary.json`。图表重建、LaTeX 编译、原始轨迹回放的要求见[复现说明](docs/weld/REPRODUCING.md)。

当前公开内容包括论文、底表、公开任务卡、评估器代码和图表脚本。原始响应、完整源数据和验证标签属于独立完整归档；公共仓库的数值复核不需要它们，完整轨迹回放需要它们。说明文档逐项区分这两种复现。
